# R3F + WebGL Maximalist Portfolio — Technical Playbook (2026-06)

> Engineering reference for a maximalist React Three Fiber + WebGL portfolio on
> **Next.js 15 (App Router) / React 19**. Multiple interactive 3D scenes, premium
> GSAP/Framer 2D motion, 60fps target, graceful mobile degradation.
> Research date: 2026-06-02. Sources are primary (pmndrs docs, GitHub, Codrops,
> Maxime Heckel, GSAP forums). Re-verify package versions before the build.

---

## Bottom line

Build on **R3F v9 + React 19** with the **pmndrs `react-three-next` global-canvas
architecture** (single persistent `<Canvas>` + `<View>` + `tunnel-rat`). Drive
scroll with **Lenis on `gsap.ticker` + GSAP ScrollTrigger** (NOT drei
ScrollControls for a multi-section DOM-heavy page). Gate every heavy scene behind
`frameloop="demand"` / IntersectionObserver / `useDetectGPU` / `prefers-reduced-motion`.
This is the only combination where DOM layout, smooth scroll, pinning, and WebGL
all share one RAF loop and stay in sync.

### Next.js 15 App Router gotchas (the four that bite)

1. **`'use client'` on every canvas file.** three.js touches `window`/`document`;
   those don't exist during SSR. Any module importing three or R3F must be a
   client component.
   — https://r3f.docs.pmnd.rs/getting-started/installation
2. **Dynamic import with `ssr: false`.** Import the Canvas wrapper via
   `next/dynamic` with `{ ssr: false }` from a Server Component so it never renders
   on the server (avoids hydration mismatch + `window is not defined`).
   — https://r3f.docs.pmnd.rs/getting-started/installation
3. **R3F v9 required.** v8 + React 19 = runtime errors. Confirm v9.
   — search result, R3F installation docs (noqta.tn tutorial flags the same).
4. **`useSearchParams()` needs a `<Suspense>` ancestor** in Next 15 static
   prerender, unrelated to 3D but a frequent build-time failure on these sites.

```tsx
// app/(canvas)/Scene.client.tsx
'use client'
import { Canvas } from '@react-three/fiber'
export default function Scene({ children }) {
  return <Canvas dpr={[1, 2]} gl={{ antialias: true }}>{children}</Canvas>
}

// app/page.tsx  (server component)
import dynamic from 'next/dynamic'
const Scene = dynamic(() => import('./(canvas)/Scene.client'), { ssr: false })
```

## 2. Architecture: single persistent global canvas (`react-three-next`)

For a multi-scene site, **do not mount a new `<Canvas>` per section**. Use the
pmndrs `react-three-next` starter pattern: **one persistent canvas at the root**,
and portal 3D content into it from anywhere in the DOM via a `<View>` component
backed by `tunnel-rat`.

- Anything inside `<View>` renders in the shared 3D context.
- `gl.scissor` cuts the single canvas viewport into segments so each `<View>`
  draws only in its DOM rectangle — many "scenes," one WebGL context, one RAF.
- The canvas is **not unmounted on navigation**, so 3D state and the GL context
  persist across routes (essential for WebGL page transitions, §6).
- Bootstrap: `npx create-r3f-app next my-app -ts`.

```tsx
<div className="relative h-96">
  <View className="absolute inset-0">
    <Dog scale={2} />
    {/* optional <OrbitControls/>, lights, etc. */}
  </View>
</div>
```

— https://github.com/pmndrs/react-three-next/blob/main/README.md
— https://github.com/pmndrs/tunnel-rat

**Why this over per-section canvases:** multiple WebGL contexts compete for GPU,
blow the browser context limit (~8-16), and can't share a postprocessing pass or
a page-transition shader. One canvas + scissored Views is the maximalist-site
standard.

## 3. Scroll-driven 3D — drei ScrollControls vs Lenis + GSAP ScrollTrigger

### Recommendation: **Lenis + GSAP ScrollTrigger** for this build.

| | drei `ScrollControls` | Lenis + GSAP ScrollTrigger |
|---|---|---|
| Best for | Self-contained, canvas-dominant pages where the whole page IS the 3D scene | Multi-section sites with real DOM content + a few 3D Views |
| DOM layout | Wants its own scroll container; HTML goes in `<Scroll html>` | Native document scroll; DOM laid out normally |
| Pinning | **Conflicts** with ScrollTrigger `pin` — documented breakage | First-class `pin`, `scrub`, `snap` |
| API into useFrame | `useScroll()` → `offset/range/curve/visible` | Read ScrollTrigger progress, or a Lenis scroll value, in `useFrame` |
| Maximalist multi-section | Awkward | Natural fit |

**Known conflict:** drei `ScrollControls` and GSAP `ScrollTrigger` `pin` do not
play well together — multiple GSAP-forum threads confirm.
— https://gsap.com/community/forums/topic/40114-scrolltrigger-pin-and-dreis-scrollcontrols-dont-play-well-together/
— https://gsap.com/community/forums/topic/42169-pinning-the-content-in-scroll-trigger-while-using-the-react-three-fiber-and-react-three-drei/

### drei ScrollControls API (use only if a section is fully canvas-driven)

`<ScrollControls pages damping distance horizontal infinite eps maxSpeed>` wraps
children; `<Scroll>` holds 3D content, `<Scroll html>` holds DOM content.
Inside `useFrame`, `const data = useScroll()` gives:

- `data.offset` — scroll position 0→1, dampened
- `data.delta` — scroll delta 0→1, dampened
- `data.range(start, length, margin?)` — 0→1 within a segment
- `data.curve(start, length, margin?)` — 0→1→0 within a segment (in/out)
- `data.visible(start, length, margin?)` — boolean for conditional work

Defaults: `pages=1`, `damping=0.2`, `distance=1`, `eps=0.00001`.
— https://drei.docs.pmnd.rs/controls/scroll-controls

### Lenis + GSAP path: drive uniforms / camera from ScrollTrigger

Use ScrollTrigger `scrub` to animate a plain object (or `gsap.to` a uniform proxy),
and read camera/object targets in `useFrame` with `lerp` for smoothing. ScrollTrigger
owns DOM pinning and section snapping; R3F `useFrame` owns the GL update.
— https://wawasensei.hashnode.dev/scroll-animations-with-react-three-fiber-and-gsap

## 4. Signature scene techniques (code-level pointers)

### a) Custom GLSL shader material — `shaderMaterial` + `extend`
Use drei's `shaderMaterial(uniforms, vertex, fragment, onInit)` helper, then
`extend({ MyMaterial })` to get a JSX element. Update uniforms in `useFrame`
(`mat.uTime = clock.elapsedTime`), animate `uProgress` via GSAP or a Framer
`MotionValue.get()`.
— https://tympanus.net/codrops/2024/12/02/how-to-code-a-shader-based-reveal-effect-with-react-three-fiber-glsl/
— https://blog.maximeheckel.com/posts/the-study-of-shaders-with-react-three-fiber/

```js
const ImageRevealMaterial = shaderMaterial(
  { uTexture: null, uTime: 0, uProgress: 0 },
  vertexShader, fragmentShader,
  (self) => { self.transparent = true }
)
extend({ ImageRevealMaterial })
// <imageRevealMaterial ref={ref} />  then ref.current.uProgress = ...
```

### b) Particle fields — `<points>` + `bufferAttribute` + `shaderMaterial`
For up to ~tens of thousands: `<points>` with `<bufferGeometry>` and
`<bufferAttribute attach="attributes-position" count array itemSize={3} />`,
a `<shaderMaterial>` setting `gl_PointSize` in the vertex shader and
`blending={THREE.AdditiveBlending}` for saturated glow. Animate in the vertex
shader via a `uTime` uniform (GPU) — do NOT rewrite the position array per frame
on the CPU.
For **hundreds of thousands**: FBO / GPGPU — simulate positions in a fragment
shader into a `useFBO` render target via `createPortal` (off-screen scene), then
read that texture as a uniform in the display `<points>` shader.
— https://blog.maximeheckel.com/posts/the-magical-world-of-particles-with-react-three-fiber-and-shaders/

### c) Glass / transmission — drei `MeshTransmissionMaterial`
Improved `MeshPhysicalMaterial` with chromatic aberration, roughness blur,
anisotropic blur, distortion, and the ability to "see" other transmissive objects.
Key props (defaults): `transmission=1`, `thickness=0`, `roughness=0`,
`chromaticAberration=0.03`, `anisotropicBlur=0.1`, `distortion=0`,
`distortionScale=0.5`, `temporalDistortion=0.0`, `samples=6`, `resolution`
(undefined = fullscreen), `backside=false` (+`backsideThickness`,
`backsideResolution`), `ior`.
**Perf:** causes an extra render pass of the scene per material — keep `samples`
and `resolution` low; for rough glass use a tiny resolution (~32). Avoid many
transmissive meshes on mobile.
— https://drei.docs.pmnd.rs/shaders/mesh-transmission-material
— https://discourse.threejs.org/t/meshtransmissionmaterial-more-realistic-glas-epoxy-gelatin/46522

### d) Postprocessing — `@react-three/postprocessing`
Wrap effects in `<EffectComposer>`; the underlying `EffectPass` auto-merges them
into the fewest passes. Common chain: `Bloom`, `ChromaticAberration`, `Noise`,
`Vignette`, `N8AO` (preferred over stock SSAO), `ToneMapping`.
**Selective bloom is material-driven:** Bloom is selective by default — push a
material's emissive color out of the 0–1 range to make it bloom; you don't toggle
it on the pass.
— https://react-postprocessing.docs.pmnd.rs/effects/bloom
— https://react-postprocessing.docs.pmnd.rs/effects/chromatic-aberration
— https://github.com/pmndrs/react-postprocessing

### e) 3D text — drei `<Text>` (troika under the hood)
Use `<Text>` from drei for SDF text-as-geometry (crisp, cheap). For volumetric/
extruded text use `<Text3D>` + a font JSON. Keep instances low; troika SDF is far
cheaper than extruded geometry.
— https://drei.docs.pmnd.rs (Text / Text3D)

### f) Image → WebGL hover distortion (RGB shift / displacement)
Render the image to a textured plane (`useTexture`), pass a `uMouse`/`uHover`
uniform, and in the fragment shader offset the R/G/B channel UVs by different
multipliers (e.g. R ×0.6, G/B ×0.9) to split the spectrum at distortion edges;
drive `uHover` with `lerp` for smooth in/out. A displacement-image approach
(transition between two images via a displacement map) is the classic alt.
— https://tympanus.net/codrops/2019/10/21/how-to-create-motion-hover-effects-with-image-distortions-using-three-js/
— https://tympanus.net/codrops/2020/04/14/interactive-webgl-hover-effects/
— https://blog.maximeheckel.com/posts/the-study-of-shaders-with-react-three-fiber/

## 5. Performance — the API surface that keeps you at 60fps

All from the R3F scaling-performance doc + drei, unless noted.
— https://r3f.docs.pmnd.rs/advanced/scaling-performance

| Lever | API / component | Note |
|---|---|---|
| On-demand render | `frameloop="demand"` on `<Canvas>` | Renders only on prop change. Best for mostly-static scenes. |
| Manual frame | `invalidate()` (from `useThree`) | Request a frame after mutating outside React (e.g. GSAP tween). Does NOT render immediately. |
| Frame on animation only | `frameloop="demand"` + `invalidate()` per tick while an animation/GLTF clip is active | — https://github.com/pmndrs/react-three-fiber/discussions/1800 |
| Adaptive resolution | `<AdaptiveDpr pixelated />` (drei) + clamp `dpr={[1, 2]}` | Drops DPR during movement; clamp upper bound on mobile. |
| Adaptive events | `<AdaptiveEvents />` (drei) | Disables raycasting during regression. |
| Perf governor | `<PerformanceMonitor onIncline onDecline onChange flipflops onFallback>` (drei) | Averages FPS; raise/lower quality. Pair with `performance.setMax`. |
| Regression on interact | `regress()` via `useThree(s => s.performance.regress)`; read `performance.current` | Config: `<Canvas performance={{ min: 0.5, debounce: 200 }}>`. |
| GPU tiering | `useDetectGPU()` (drei) → tier + `isMobile` | Show a static fallback for tier 0/1; cap `setMax` unless top tier. |
| Instancing | `<instancedMesh>` + `setMatrixAt()`, or drei `<Instances>/<Instance>` | Thousands of objects in one draw call. |
| LOD | `<Detailed distances={[0,10,20]}>` (drei) | Swap mesh resolution by camera distance. |
| Resource reuse | `useGLTF` / `useLoader` (cached by URL); `useMemo` geometries/materials | Never recreate geometry/material per render. |
| Concurrency | React 19 `startTransition` for heavy mounts | Keeps 60fps while loading. |
| Off-main-thread | `@react-three/offscreen` (OffscreenCanvas worker) | Hero scenes; feature-detect and degrade. |

### Lazy-mount + viewport gating

- Wrap each scene/`<View>` in an **IntersectionObserver** (threshold ~0.1).
  Common pattern: toggle the canvas/scene `frameloop` between `'always'` and
  `'never'` based on visibility so off-screen scenes cost nothing.
  — https://r3f.docs.pmnd.rs/advanced/scaling-performance (and search result above)
- Code-split scene modules with `next/dynamic` so three doesn't ship until needed.
- `<Suspense>` low-res model fallback → high-res swap for perceived speed.

### Mobile / accessibility fallbacks (mandatory on a maximalist site)

- `useDetectGPU` tier ≤1 or `isMobile` → render a static image / CSS gradient
  instead of the heavy scene; disable transmission + postprocessing.
- `prefers-reduced-motion: reduce` → freeze scenes (no auto-rotation, no scrub
  parallax), skip page-transition shaders, drop particle counts to 0.
  General React pattern: a `usePrefersReducedMotion` hook gating motion.
  — https://www.joshwcomeau.com/react/prefers-reduced-motion/
- Respect `navigator.connection.saveData` and small screens → skip 3D entirely.
- Cap `dpr` at 2 (or 1.5 on mobile); transmission/postprocessing are the first
  things to drop under regression.

## 6. Smooth scroll — Lenis + GSAP ScrollTrigger + R3F on ONE RAF loop

**Root cause of jank:** Lenis, GSAP, and R3F each run their own
`requestAnimationFrame`. When Lenis updates scroll on its loop and ScrollTrigger
reads on its own tick, you get 1–2 frame desync. **Fix: make Lenis tick from
`gsap.ticker` and let everything share that clock.**

Canonical wiring (from Lenis README + GSAP forum consensus):

```js
// 'use client' — run once on mount (e.g. a <SmoothScroll> provider)
import Lenis from 'lenis'
import { gsap } from 'gsap'
import { ScrollTrigger } from 'gsap/ScrollTrigger'
gsap.registerPlugin(ScrollTrigger)

const lenis = new Lenis({ duration: 1.2, syncTouch: true })

lenis.on('scroll', ScrollTrigger.update)          // keep ST in sync with Lenis
gsap.ticker.add((time) => lenis.raf(time * 1000)) // Lenis ticks from GSAP (s→ms)
gsap.ticker.lagSmoothing(0)                        // no lag compensation
```

- With `lenis/react`, set **`autoRaf={false}`** on `<ReactLenis>` so Lenis does
  NOT spawn its own RAF — GSAP drives it. (The forum-quoted variant used
  `lenis.raf(time * 600)` for a slower feel; `time * 1000` is the README default.)
- Call `ScrollTrigger.refresh()` after mount/layout settles so trigger positions
  match the Lenis-managed scroll height.
- R3F's `useFrame` already runs on its own loop, but because it reads the same
  camera/uniform targets that ScrollTrigger writes (with `lerp` smoothing), the
  visual result stays coherent. The critical sync is Lenis↔ScrollTrigger; R3F
  follows the shared state.
- **Mobile caveat:** several reports of iOS jank when wrapping all content in
  `ReactLenis` — consider disabling Lenis on touch / small screens and falling
  back to native scroll.

Sources:
— https://github.com/darkroomengineering/lenis/blob/main/README.md
— https://gsap.com/community/forums/topic/40426-patterns-for-synchronizing-scrolltrigger-and-lenis-in-reactnext/
— https://gsap.com/community/forums/topic/34814-scrolltrigger-with-lenis-smooth-scroll-problem-with-the-scrollerproxy-setup/
— https://devdreaming.com/blogs/nextjs-smooth-scrolling-with-lenis-gsap

**Alternative:** GSAP's own `ScrollSmoother` (native to GSAP, no Lenis sync
needed) — a GSAP-forum admin recommends it; teams pick Lenis for licensing and
`position: fixed` behavior. If you want zero RAF-sync code, evaluate ScrollSmoother.

**Pre-built rig:** `14islands/r3f-scroll-rig` syncs 3D meshes to DOM elements and
handles much of this glue if you don't want to wire it by hand.
— https://github.com/14islands/r3f-scroll-rig

## 7. Page transitions in Next App Router (3 viable approaches)

1. **Persistent global canvas + shader transition (best for this build).**
   Because the `react-three-next` canvas survives navigation (§2), run a full-screen
   transition shader (band sweep / dissolve / displacement) on the persistent
   canvas while the new route's DOM swaps underneath. State carries across routes
   for free. This is the maximalist-correct approach.
   — https://github.com/pmndrs/react-three-next/blob/main/README.md

2. **Framer Motion `AnimatePresence` with the FrozenRouter fix.** App Router
   updates context during navigation, unmounting components mid-animation and
   breaking `AnimatePresence`. The known fix is a **FrozenRouter** wrapper (freeze
   the router context while exit animations run) + `LayoutTransition`.
   — https://www.imcorfitz.com/posts/adding-framer-motion-page-transitions-to-next-js-app-router
   — https://blog.olivierlarose.com/articles/nextjs-page-transition-guide
   For canvas-aware transitions, combine `AnimatePresence` for DOM with a uniform
   tween on the persistent canvas.
   — https://eriksachse.medium.com/how-to-use-r3f-next-js-add-page-transitions-with-framer-motion-in-the-canvas-and-dom-95c33c34ce70

3. **Off-the-shelf: `glimm`.** Shader-driven page transitions for React/Next —
   a single WebGL band sweeps across while routes swap, sub-10kb, GPU-composited,
   wrap app in `GlimmProvider`. Fastest path if a band-sweep aesthetic fits.
   — https://glimm.dev/

> View Transitions API exists and is promising but, as of this research, the
> persistent-canvas + shader approach gives more control for WebGL transitions on
> a maximalist site. Re-check VT API maturity at build time.

## Recommended stack (the decision)

- **Renderer:** R3F v9 + drei + @react-three/postprocessing on three (pinned).
- **Architecture:** `react-three-next` global canvas — single `<Canvas>`, `<View>`
  + `tunnel-rat`, `gl.scissor` segments. `npx create-r3f-app next my-app -ts`.
- **Scroll:** Lenis on `gsap.ticker` + GSAP ScrollTrigger (`autoRaf={false}`,
  `lagSmoothing(0)`, `ScrollTrigger.refresh()`). NOT drei ScrollControls for the
  multi-section page (pin conflict). Consider `r3f-scroll-rig` to save glue code.
- **2D motion:** `motion/react` (Framer) for DOM micro-interactions + transitions.
- **Signature scenes:** custom `shaderMaterial`, GPU particle fields (FBO for big
  counts), `MeshTransmissionMaterial` glass (low samples/res), postprocessing
  bloom/CA/noise, drei `<Text>`, image-hover RGB-shift shaders.
- **Transitions:** shader sweep on the persistent canvas (primary); Framer
  `AnimatePresence` + FrozenRouter for DOM (secondary); `glimm` if it fits.

## Perf checklist (per scene, before shipping)

- [ ] `frameloop="demand"` on static scenes; `invalidate()` after external mutations.
- [ ] `dpr={[1, 2]}` clamp (1.5 cap on mobile); `<AdaptiveDpr>` + `<AdaptiveEvents>`.
- [ ] `<PerformanceMonitor>` governing quality; `performance={{ min: 0.5 }}`.
- [ ] `useDetectGPU` → static fallback for tier ≤1 / mobile; disable transmission + postprocessing there.
- [ ] IntersectionObserver gates each `<View>`; off-screen scenes set frameloop `'never'`.
- [ ] Instancing (`<Instances>` / `instancedMesh`) for repeated geometry; `<Detailed>` LOD for hero meshes.
- [ ] Geometries/materials `useMemo`'d; GLTF via `useGLTF` (URL-cached).
- [ ] `MeshTransmissionMaterial`: `samples` low, `resolution` low/32 for rough glass; few instances.
- [ ] Postprocessing: minimal effect chain; selective bloom via emissive >1, not extra passes.
- [ ] `prefers-reduced-motion` freezes motion + skips transition shaders; `saveData`/small-screen skips 3D.
- [ ] Lenis disabled on iOS/touch if jank; scroll↔ScrollTrigger sync verified (no 1–2 frame lag).
- [ ] One persistent canvas total — verify no per-section `<Canvas>` leaked in.
